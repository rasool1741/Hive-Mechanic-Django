# طرح اتصال Graph به Runtime

## انتخاب Runtime

در `game_action` وجود `definition.graph.nodes` در نسخه Published، پس از احراز نسخه و Session، Graph Runtime را فعال می‌کند. تعریف‌های قدیمی فاقد Graph بدون تغییر از مسیر Sequence/InteractionCard استفاده می‌کنند.

## وضعیت Node

برای جلوگیری از Migration غیرضروری، Node جاری در `Session.session_state['graph_node_id']` ذخیره می‌شود. اگر مقدار وجود نداشته باشد، سرور `graph.start` را به‌عنوان Node اولیه انتخاب می‌کند. این مقدار از کلاینت پذیرفته نمی‌شود و بعد از هر Action معتبر فقط سرور آن را تغییر می‌دهد.

## عملیات و ابزارها

Endpoint موجود `POST /builder/api/v1/sessions/<id>/actions` حفظ شده است. Graph Runtime همان کنترل‌های احراز هویت، مالکیت Session، شهر فعال، نسخه Published، قفل تراکنشی، Replay و ScoreLedger را استفاده می‌کند. ابزارهای `gps` و `qr` در metadata Node به‌ترتیب اعتبارسنجی GPS/Geofence و QR امضاشده را اجباری می‌کنند. ابزارهای `hint`، `timer`، `quiz` و `text_input` نیز در همین Endpoint با زمان و تنظیمات Published اجرا می‌شوند؛ Media هنوز metadata است.

Hint از مدل Hint یا تنظیمات Node خوانده و هزینه‌اش سروری ثبت می‌شود؛ Timer زمان Unix سرور را در Session نگه می‌دارد؛ Quiz و Text با تنظیمات Published مقایسه می‌شوند. ابزار ناشناخته fail closed است.

Media محتوایی با `operation=media` و تنظیمات Published شامل `file_id` و `media_type` اجرا می‌شود. سرور فایل را از `django-filer.File` می‌خواند، MIME ثبت‌شده را با نوع مورد انتظار تطبیق می‌دهد و URL ارسالی کلاینت را هرگز قبول نمی‌کند. آپلود مدرک توسط بازیکن در این فاز فعال نشده است.

## انتخاب Edge

Edgeها فقط از `source` برابر Node جاری بررسی می‌شوند. فقط نبود شرط یا مقدار `null` یعنی «Edge بدون شرط». شرط معتبر دقیقاً `{variable, equals}` است (یا `{key, equals}`؛ داشتن هم‌زمان `variable` و `key`، کلید ناشناخته، `{}`، `[]`، رشته‌ی خالی، `0`، `false`، نام متغیر خالی یا غیررشته‌ای نامعتبر است و **هرگز** به‌معنی «همیشه درست» نیست). شرط **فقط** از `Session.session_state['graph_vars']` می‌خواند؛ هیچ کلید دیگری از Session و هیچ مقداری از درخواست کلاینت نمی‌تواند شرط را برقرار کند. اعتبارسنجی انتشار و Runtime هر دو از یک تابع (`parse_condition` در `builder/urban_tools.py`) پیروی می‌کنند. Node بعدی، امتیاز، تکمیل و `graph_node_id` همگی توسط سرور تعیین می‌شوند.

### قرارداد پاسخ تأییدشده و شرط Edge

- ابزار Quiz (`settings.answer`) و Text (`settings.exact`) می‌توانند یک مقدار یا **لیستی از پاسخ‌های مجاز** داشته باشند. پاسخ خارج از لیست همچنان رد می‌شود (۴۰۳) و مرحله جابه‌جا نمی‌شود. Text بدون `exact` هیچ متغیری نمی‌سازد.
- پس از تأیید پاسخ، سرور **مقدار تعریف‌شده توسط مدیر** (نه متن خام بازیکن) را در `graph_vars` می‌نویسد. نام متغیر `settings.variable` است و در نبود آن `<node_id>.quiz` یا `<node_id>.text`.
- نوشتن متغیر فقط همراه انتقال موفق مرحله انجام می‌شود. اگر Edge معتبری پیدا نشود یا بیش از یک Edge منطبق باشد، پاسخ ۴۰۹ است و هیچ رویدادی، امتیازی یا متغیری ثبت نمی‌شود.
- پاسخ‌های سرور هرگز پاسخ صحیح، `exact`، نام یا مقدار متغیر و `session_state` را برنمی‌گردانند.
- **عملیات مجاز** در Node فقط `complete` (پیش‌فرض)، `hint` و `media` است. هر `operation` دیگری (از جمله `null`، رشته‌ی خالی، حروف متفاوت یا نوع غیررشته) پیش از اجرای هر ابزار با ۴۰۰ رد می‌شود؛ بنابراین نمی‌تواند اعتبارسنجی Quiz/Text یا حداقل زمان Timer را دور بزند. انتقال به Node بعدی فقط از مسیر `complete` ممکن است.

- **مقدار canonical:** برای Text دقیقاً برابر متن `strip`‌شده‌ی بازیکن است (مقایسه دقیق و حساس به حروف؛ متن خالی هرگز تطبیق نمی‌خورد). برای Quiz مقدار تعریف‌شده توسط مدیر است و مقایسه‌ی آن بدون حساسیت به حروف و فاصله‌ی ابتدا/انتهاست. به همین دلیل مقدار مجاز Text باید خالی نباشد، فقط فاصله نباشد، فاصله‌ی ابتدا یا انتها نداشته باشد و در `max_length` (پیش‌فرض ۱۰۰۰) جا شود؛ وگرنه بازیکن هیچ‌وقت نمی‌تواند آن را وارد کند و انتشار رد می‌شود. فاصله‌ی داخل متن مجاز است.
- **کنترل ساختار در Runtime:** پیش از هر نوشتن (شروع Timer، نگه‌داشتن پاسخ، انتقال مرحله)، Runtime ساختار Edgeهای خروجی Node جاری را با **همان قواعد انتشار** (`branch_problems`) می‌سنجد. اگر Node شاخه‌ساز ترکیب شرطی/بی‌شرط، شرط نامعتبر یا بیش از یک متغیر داشته باشد (مثلاً در نسخه‌ای که قبلاً منتشر شده)، پاسخ ۴۰۹ است و هیچ رویداد، امتیاز، متغیر یا انتقالی ثبت نمی‌شود، حتی اگر فقط یکی از Edgeها برقرار باشد. `hint` و `media` از این کنترل مستثنی‌اند و مثل قبل کار می‌کنند.

#### قواعد اعتبارسنجی هنگام انتشار برای Nodeهای شاخه‌ساز

یک Node شاخه‌ساز Nodeای است که حداقل یک Edge خروجی با شرط (غیر `null`) دارد. چنین Nodeای باید:

1. **همه‌ی Edgeهای خروجی‌اش شرطی باشند** (ترکیب شرطی و بی‌شرط ممنوع است) و همه‌ی شرط‌ها معتبر باشند.
2. فقط از **یک متغیر** برای تصمیم‌گیری استفاده کند؛ استفاده از چند متغیر (که می‌تواند شرط‌ها را هم‌پوشان یا مبهم کند) رد می‌شود.
3. آن متغیر را ابزار Quiz/Text اعلام کرده باشد، و **Node سازنده‌ی متغیر روی تمام مسیرهای ممکن از `start` تا Node شاخه‌ساز قرار داشته باشد** (Node سازنده، خودِ Node شاخه‌ساز را Dominate کند یا خودش باشد). متغیری که فقط روی بعضی مسیرها ساخته می‌شود یا فقط بعد از آن Node ساخته می‌شود رد می‌شود.
4. برای **هر پاسخ مجاز** آن متغیر دقیقاً یک Edge خروجی داشته باشد، حتی وقتی Node شاخه‌ساز با Node سازنده فرق می‌کند. `equals` باید یکی از پاسخ‌های مجاز (رشته) باشد و تکراری نباشد.

موارد دیگری که انتشار را رد می‌کنند: نام متغیر تکراری، فهرست پاسخ مجاز خالی یا تکراری، و پاسخ مجاز Text که خالی، فقط فاصله، دارای فاصله‌ی ابتدا/انتها یا بلندتر از `max_length` باشد.

## سازگاری و هم‌زمانی

`select_for_update()` و `transaction.atomic()` روی Session از اعمال هم‌زمان جلوگیری می‌کنند. `SessionEvent(session,event_id)` برای Replay یکتا است. نسخه Published در طول Session ثابت می‌ماند. Graph Runtime هنوز با Sequence/InteractionCard نگاشت یک‌به‌یک ندارد؛ بنابراین ابزارهای کارت‌محور قدیمی باید در فاز بعدی به قرارداد Graph متصل شوند.
